ConflictCore

Conflict Resolution-Based Multi-User File Management System

ConflictCore guarantees safe concurrent multi-user file operations through deterministic OS process scheduling (FCFS, SJF, Priority), granular file version tracking, concurrent write contention detection with interactive conflict resolution, and transactional MySQL relational database persistence.

PROJECT CAPABILITIES & ARCHITECTURE

Engineered for Concurrent Multi-User Operations

A modular system coupling a Node.js REST API with an in-memory Operating Systems module and persistent MySQL relational storage.

File Management

Hierarchical Storage & Directory Explorer
Implemented

Upload, download, create folders, rename, move, and delete files with safe local disk staging, MIME validation, and transactional synchronization.

  • Multi-file upload staging to disk with file-size and type validation
  • Nested directory navigation with interactive path breadcrumbs
  • Atomic folder CRUD with cycle prevention and child re-parenting

OS Process Scheduling

CPU Dispatching & Lifecycle Engine
Implemented

Coordinates concurrent file operations using deterministic CPU scheduling algorithms with real-time Gantt timeline and performance metrics.

  • First-Come-First-Served (FCFS), Shortest Job First (SJF), and Priority policies
  • Strict state transitions: READY → RUNNING → WAITING → COMPLETED
  • Calculates arrival, burst, completion, waiting, and turnaround times

Version Tracking & Conflict Resolution

Concurrent Write Contention & Branching
Implemented

Maintains historical revision logs for files and detects simultaneous write contention when competing operations attempt modifications.

  • Detailed version history logging author, operation type, and timestamps
  • Detects write contention between active lock holders and queued waiters
  • Three resolution policies: Keep Current, Accept Incoming, or Branch as Copy

MySQL Database Integration

Relational Persistence & User Authentication
Implemented

Persistent storage under MySQL 8.0 InnoDB engine with ACID transactions, foreign-key relational integrity, and secure password hashing.

  • Normalized relational schema for users, folders, files, and audit records
  • Bcrypt password hashing with 10 salt rounds for secure authentication
  • Atomic transactions preventing orphaned data on deletions and moves
ℹ
Architecture Scope & Phase 2 Roadmap

The four subsystems above (File Management, OS Process Scheduling, Version Tracking with Conflict Resolution, and MySQL Database Integration) represent the verified, operational core of this project. Advanced multi-resource distributed lock managers and dynamic deadlock graph cycle prevention represent subsequent Phase 2 milestones and are currently maintained in their initial research and simulation baseline.
